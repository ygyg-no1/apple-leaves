## 摘要

苹果叶片病害的早期识别对保障产量与品质具有重要意义。传统人工巡检效率低、主观性强，难以满足规模化果园管理需求。本文围绕本仓库实现的「苹果叶病害智能检测系统」，将病害识别形式化为 **多类别目标检测问题**：在 RGB 图像上同时输出病斑或叶片区域的 **边界框位置** 与 **四类语义标签**（黑腐相关、锈病、健康、疮痂相关等，以数据集标注为准），并给出置信度供阈值筛选。

系统基于 **Ultralytics YOLO** 训练与推理管线，网络结构采用 **YOLOv13** 风格的骨干与多尺度检测头（参见 `ultralytics/cfg/models/v13/yolov13.yaml`），在自定义苹果叶数据集（YOLO txt 标注）上进行 **迁移学习与微调**。应用层提供 **PySide6 桌面工作站**：支持模型加载、图像与视频推理、检测框类别统计、柱状图导出，以及基于 **DeepSeek 大语言接口** 的农艺管理文字建议（不参与视觉判别）。

本报告从 **绪论、理论基础、总体设计、详细实现、实验分析、结论展望** 六章展开，并给出评价指标说明与后续改进方向，可供课程设计、毕业设计或内部技术归档使用。

**关键词**：苹果叶片病害；目标检测；YOLOv13；深度学习；迁移学习；人机交互；技术报告

## Abstract

This technical report describes an apple leaf disease detection system built upon Ultralytics YOLO with a YOLOv13-style architecture. The task is formulated as multi-class object detection on RGB images, producing bounding boxes and four semantic categories aligned with project annotations. Training follows transfer learning from publicly available pretrained weights; inference is exposed via scripts and a PySide6 desktop client with optional LLM-based agronomic text advice through the DeepSeek API. Chapters cover motivation, theory, system design, implementation, experimental protocol, and conclusions.

**Keywords**: apple leaf disease; object detection; YOLOv13; deep learning; transfer learning; HMI; technical report

# 第一章 绪论

## 1.1 研究背景与意义

苹果是我国主要经济果树之一，叶部病害（如黑腐、锈病、疮痂等）若发现滞后，易导致光合能力下降、果实品质劣化甚至大面积流行。传统防治依赖农技人员田间巡查，存在 **成本高、频次有限、主观判断差异大** 等问题。随着移动终端与高清相机的普及，利用 **可见光图像** 进行自动化筛查成为可能。

本系统在工程上将「是否患病、病灶在何处」转化为 **目标检测** 输出：不仅对整图做语义判断，而且在像素平面上给出 **空间定位**，便于后续 **计数统计、重点区域标注、与人机协同决策**（如结合大模型的文字解读）。该路线适用于叶片占据画面主体或病斑需单独框出的应用场景。

## 1.2 国内外研究现状简述

植物病害识别主流路线包括：（1）基于传统图像特征与机器学习分类器；（2）基于深度卷积网络的 **图像级分类**；（3）基于检测或分割网络的 **定位级识别**。随着实时性要求提升，**单阶段目标检测器**（如 YOLO 系列）因结构紧凑、推理延迟低，在农业物联网与边缘设备落地中具有优势。

YOLOv13 在统一框架下引入 **超图增强的自适应视觉感知** 等机制以强化特征表达（详见论文）。本仓库在 Ultralytics 代码库中集成该结构配置，并在 **小规模专用数据集** 上完成领域微调，属于典型的 **通用检测基础模型 + 垂直领域数据** 范式。

## 1.3 本文工作与报告结构

**本文工作**可概括为：（1）建立四类苹果叶病害 YOLO 检测数据管线；（2）基于预训练权重完成模型训练与推理验证；（3）实现带登录、统计与可选 LLM 建议的桌面工作站。

**报告结构**：第二章给出检测与 YOLO 相关理论；第三章描述需求与架构；第四章为数据、模型与软件实现细节；第五章给出实验范式与结果分析框架；第六章总结并展望。

# 第二章 相关理论与技术基础

## 2.1 目标检测问题描述

给定输入图像 \(I\)，目标检测模型输出有限集合 \(\{(b_i, c_i, s_i)\}\)，其中 \(b_i\) 为第 \(i\) 个候选框（常用 \(xywh\) 或两点式表示），\(c_i \in \{1,\ldots,K\}\) 为类别，\(s_i\) 为置信度。训练阶段需提供与真值框匹配的监督信号；推理阶段需通过后处理抑制冗余框。

## 2.2 单阶段检测与 YOLO 系列

**两阶段方法**（如 Faster R-CNN）先生成候选区域再分类回归，精度潜力高但结构重。**单阶段方法**（YOLO、SSD 等）在密集网格上直接预测类别与框参数，**一次前向**完成推理，更适合实时检测。YOLO 家族历经多代演进，在 Neck、Head、损失与标签分配策略上持续改进；Ultralytics 提供了统一的训练、验证与导出接口。

## 2.3 多尺度特征、损失函数与 NMS

**多尺度特征融合**：病害目标尺度变化大，需在浅层（细节）与深层（语义）特征之间建立通路，典型结构为 FPN / PAN 及其变体。本仓库 YOLOv13 配置中 `Concat`、`Upsample` 与自定义模块共同完成跨尺度融合。

**损失**：通常包含 **框回归损失**（IoU 系列）、**分类损失**（抑制难易样本不平衡时可引入 Focal 类变体），具体加权形式由框架实现。

**NMS**：对高重叠候选框按 IoU 阈值抑制，保留高置信度代表框，避免同一病灶重复计数。

**Letterbox**：保持宽高比的缩放与填充，减轻几何形变；标注需随相同几何变换同步（由数据加载器完成）。

## 2.4 迁移学习与评价指标

**迁移学习**：源域（大规模通用检测数据）预训练提供低层通用特征，目标域（苹果叶数据）微调使高层语义对齐病害外观。

**常用指标**：Precision、Recall、PR 曲线、AP、mAP@0.5、mAP@0.5:0.95。农业应用中建议 **分病种报告召回率**，避免「平均指标掩盖弱势类别」。

# 第三章 需求分析与总体设计

## 3.1 任务需求与功能需求

**任务需求**：输入田间/温室 RGB 图像或视频帧，输出病害相关区域的检测框及类别，置信度可调。

**功能需求**（与本仓库实现对应）：

| 需求编号 | 描述 | 实现位置 |
|----------|------|----------|
| F1 | 加载自定义 `.pt` 权重 | `desktop_app/main_ui.py`、`yolo_worker.py` |
| F2 | 单张图像检测与结果保存 | `predict` + `OUTPUT_ROOT` |
| F3 | 视频逐帧检测与写出 | `yolo_worker.py` + OpenCV |
| F4 | 类别计数与柱状图 | `charts.py` |
| F5 | 本地登录 | `auth_store.py` |
| F6 | 可选 DeepSeek 文字建议 | `deepseek_client.py` |

## 3.2 数据集与类别体系

配置文件：`datasets/data.yaml`。类别数 `nc=4`，名称映射包含 Apple__BlackRot、Apple__CedarRust、Apple__Healthy、Apple__Scab。**实际语义以标注规范文档为准**，本报告不一概而论病理学诊断标准。

## 3.3 系统总体架构

系统分为 **数据层、模型层、应用层**：

- **数据层**：图像、`data.yaml`、YOLO txt 标注；
- **模型层**：YOLOv13 配置 + PyTorch 权重训练与推理；
- **应用层**：桌面 GUI（PySide6）、HTTP 调用 LLM（可选）。

逻辑数据流：**图像 → 预处理 → 骨干/颈部/检测头 → 解码与 NMS → 框与类别 → 统计与可视化 →（可选）文本建议**。

# 第四章 详细设计与实现

## 4.1 数据规范与目录结构

**YOLO txt 每行**：`class_id cx cy w h`，其中 `cx,cy,w,h` 为相对图像宽高的 **0～1 归一化**中心坐标与宽高。

**像素换算**：设图像宽 \(W\)、高 \(H\)，像素框左上 \((x_1,y_1)\)、右下 \((x_2,y_2)\)，则  
\(cx=\frac{(x_1+x_2)/2}{W}\)，\(cy=\frac{(y_1+y_2)/2}{H}\)，\(w=\frac{x_2-x_1}{W}\)，\(h=\frac{y_2-y_1}{H}\)。

**目录**：`images/train`、`images/val` 等与 `data.yaml` 中 `path` 相对路径一致。

## 4.2 模型结构与训练实现

**结构定义**：`ultralytics/cfg/models/v13/yolov13.yaml`。Backbone 含 `Conv`、`DSC3k2`、`DSConv`、`A2C2f` 等；Head 含 `HyperACE`、`FullPAD_Tunnel` 等与多尺度融合；末端 `Detect` 输出绑定 `nc`（训练时被数据配置覆盖为 4）。

**训练脚本**：`train.py`。要点：`YOLO('yolov8n.pt')` 初始化；`model.train(data=..., imgsz=640, epochs=50, optimizer='AdamW', amp=True, mosaic=..., patience=...)` 等；产物位于 `runs/train/<实验名>/weights/`。

## 4.3 推理流程与脚本

**示例脚本**：`苹果叶病变检测.py` 加载 `best.pt`，对验证集目录 `predict`，`conf=0.25`，`save=True`。  

**参数**：`conf` 控制漏检与误报折中；`iou` 控制 NMS 重叠抑制强度；`imgsz` 影响分辨率与速度。

## 4.4 桌面软件设计

**入口**：`run_desktop.py`（校验 `torch` 可用后启动界面）。

**线程模型**：`YoloWorker` 运行于独立 `QThread`，通过 `Signal`/`Slot` 与主线程通信，避免 UI 阻塞及 CUDA 上下文冲突。

**模块**：`paths.py` 统一路径；`main_ui.py` 负责界面与业务编排；`yolo_worker.py` 负责 `YOLO` 加载与推理；`charts.py` 使用 Matplotlib Agg 后端绘图。

## 4.5 大语言模型辅助模块

**接口**：`https://api.deepseek.com/v1/chat/completions`，Bearer Token。  

**输入**：检测统计文本与数据来源说明；**输出**：中文农艺管理建议（经后处理去除 Markdown 符号）。  

**声明**：该输出 **不构成** 农药处方或法定诊断意见；须遵守法规与农技推广流程。

# 第五章 实验设计与结果分析

## 5.1 实验环境

建议在报告中填写：**操作系统、CPU、GPU 型号与显存、CUDA/cuDNN 版本、Python 版本、PyTorch 版本、Ultralytics 版本**。例如可在终端执行 `pip freeze` 节选核心依赖表。

## 5.2 实验方案

1. **训练**：使用 `train.py` 或等价 CLI，固定 `data.yaml`，记录 `args.yaml`。  
2. **验证**：`yolo val model=best.pt data=datasets/data.yaml`，保存终端输出的 mAP 与各类 AP。  
3. **测试集**（若有）：仅在最终轮次评估，避免调参泄漏。  
4. **消融**（可选）：对比不同 `imgsz`、`mosaic` 关闭时机或不同初始化权重对 mAP 的影响。

## 5.3 结果记录与分析要点

建议以 **表格** 列出：mAP@0.5、mAP@0.5:0.95、各类 Precision/Recall、训练耗时、单张推理耗时（ms/图）。

**定性分析**：选取 **真阳性、误检、漏检** 各若干例附图，分析是否与光照、遮挡、病斑过小有关。

# 第六章 结论与展望

本文所述系统在 **目标检测范式** 下实现了苹果叶片四类病害相关区域的定位与识别，并完成训练脚本、批量推理示例与桌面工作站的一体化落地。YOLOv13 结构为多尺度病害目标提供了较强的特征表达能力；迁移学习降低了专用数据规模下的训练难度。

**展望**：（1）扩充样本并做跨场景验证；（2）引入实例分割以精确勾勒病斑轮廓；（3）模型压缩与 TensorRT 部署以满足移动端；（4）与大模型结合时引入 RAG 与权威植保知识库以提高建议可追溯性。
